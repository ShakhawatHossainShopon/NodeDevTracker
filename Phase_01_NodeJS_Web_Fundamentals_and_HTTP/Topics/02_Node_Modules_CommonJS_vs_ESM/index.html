ফেজ ০১: Node.js ওয়েব ফান্ডামেন্টালস টপিক ০২

Node.js মডিউল সিস্টেম: CommonJS বনাম ES Modules

সহজ বাংলায় জানুন: ওয়েব অ্যাপ্লিকেশনে কোড আলাদা আলাদা ফাইলে ভাগ করার নিয়ম, require বনাম import এর পার্থক্য এবং কেন আধুনিক ওয়েবে ES Modules ব্যবহার করা হয়।

📦 ১. মডিউল সিস্টেম কেন প্রয়োজন?

বাস্তব জীবনের কোনো ওয়েব অ্যাপ্লিকেশনে (যেমন ই-কমার্স বা সোশ্যাল মিডিয়া) হাজার হাজার লাইনের কোড থাকে। আপনি যদি সব কোড একটা ফাইলেই (যেমন server.js) লিখে রাখেন, তাহলে কোড পড়া ও ম্যানেজ করা অসম্ভব হয়ে পড়বে।

মডিউল সিস্টেমের মাধ্যমে:

  • ইউজার রিলেটেড কাজগুলো userService.js এ রাখা যায়।
  • ডাটাবেসের কাজগুলো db.js এ আলাদা রাখা যায়।
  • একটি ফাইলের ফাংশন অন্য ফাইলে Export ও Import করে বারবার ব্যবহার করা যায়।

⚔️ ২. CommonJS (CJS) বনাম ECMAScript Modules (ESM)

Node.js এ মূলত দুটি মডিউল সিস্টেম কাজ করে:

১. CommonJS (CJS) - Node-এর আদি সিস্টেম

২০০৯ সালে Node.js তৈরির সময় এটি আনা হয়েছিল। ফাইল লোড করতে require() এবং এক্সপোর্ট করতে module.exports ব্যবহার করা হয়।

// CJS এ এক্সপোর্ট
const add = (a, b) => a + b;
module.exports = { add };

// CJS এ ইমপোর্ট
const { add } = require('./math.js');

২. ES Modules (ESM) - আধুনিক স্ট্যান্ডার্ড

২০১৫ সালে জাভাস্ক্রিপ্টের অফিশিয়াল স্ট্যান্ডার্ড (ES6) হিসেবে আসে। ব্রাউজার ও আধুনিক Node.js উভয় জায়গাতেই import এবং export কাজ করে।

// ESM এ এক্সপোর্ট
export const add = (a, b) => a + b;

// ESM এ ইমপোর্ট
import { add } from './math.js';

📊 গুরুত্বপূর্ণ পার্থক্যসমূহ:

বৈশিষ্ট্য CommonJS (CJS) ES Modules (ESM) ⭐ (আধুনিক)
সিনট্যাক্স require() / module.exports import / export
লোডিং মেকানিজম সিঙ্ক্রোনাস (Synchronous) অ্যাসিনক্রোনাস (Asynchronous) ও ফাস্ট
টপ-লেভেল Await সরাসরি কাজ করে না ফাংশনের বাইরেও সরাসরি await করা যায়
ব্রাউজার সাপোর্ট ব্রাউজারে সরাসরি চলে না আধুনিক সব ব্রাউজার সরাসরি সাপোর্ট করে
ফাইল পাথ __dirname, __filename আছে import.meta.url ব্যবহার করতে হয়

⚙️ ৩. আপনার প্রজেক্টে ES Modules কীভাবে চালু করবেন?

Node.js এ বাই-ডিফল্ট CommonJS কাজ করে। আপনার প্রজেক্টে আধুনিক import / export ব্যবহার করতে চাইলে দুটি সহজ উপায় আছে:

উপায় ১: package.json এ `"type": "module"` লেখা (সেরা উপায়)

আপনার প্রজেক্টের package.json ফাইলে শুধু একটি লাইন যুক্ত করে দিন:

{
  "name": "my-web-app",
  "version": "1.0.0",
  "type": "module"
}

এখন থেকে আপনার প্রজেক্টের সব .js ফাইল স্বয়ংক্রিয়ভাবে ES Module হিসেবে কাজ করবে!

উপায় ২: ফাইলের এক্সটেনশন .mjs দেওয়া

package.json পরিবর্তন না করেও যেকোনো ফাইলের নাম server.mjs দিলে Node.js সেটিকে ESM হিসেবে রান করে।

আধুনিক ব্যাকএন্ড টিপস: বর্তমানে এক্সপ্রেস, প্রিজমা (Prisma), মনগুজ (Mongoose) এবং সব আধুনিক লাইব্রেরিই ES Modules সাপোর্ট করে। তাই নতুন সব প্রজেক্টে "type": "module" ব্যবহার করাই বর্তমান ইন্ডাস্ট্রি স্ট্যান্ডার্ড।

টপিক ০২ এর প্রজেক্ট দেখতে চান?

ল্যাব ফোল্ডারে গিয়ে মডিউলার ইউটিলিটি এক্সপোর্ট ও ইমপোর্টের প্রজেক্টটি লক্ষ্য করুন।
