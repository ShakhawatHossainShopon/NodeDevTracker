Parsing URL Paths, Query Strings & HTTP Request Headers

ইনকামিং রিকোয়েস্টের পাথনেম আলাদা করা, আধুনিক WHATWG URL API দিয়ে কুয়েরি স্ট্রিং পড়া এবং রিকোয়েস্ট হেডারের ভূমিকা ও ব্যবহার।

১. `req.url` আসলে কী দেয় এবং কেন সরাসরি স্প্লিট করবেন না?

Node.js-এর নেটিভ HTTP সার্ভারে যখন কোনো ক্লায়েন্ট (যেমন ব্রাউজার বা মোবাইল অ্যাপ) রিকোয়েস্ট পাঠায়, তখন req.url প্রোপার্টিতে কিন্তু পুরো ডোমেন থাকে না (যেমন https://myapi.com/users?id=5 থাকে না)।

বরং req.url শুধুমাত্র রিলেটিভ পাথ এবং কুয়েরি অংশটুকু রিটার্ন করে: 

// যদি ক্লায়েন্ট রিকোয়েস্ট করে: http://localhost:3000/api/products?category=electronics&limit=10
console.log(req.url); 
// আউটপুট: "/api/products?category=electronics&limit=10"
⚠️ কেন `req.url.split('?')` করা অনুচিত?
অনেকে ম্যানুয়ালি স্ট্রিং স্প্লিট করে পাথ এবং কুয়েরি আলাদা করার চেষ্টা করেন। কিন্তু URL-এ স্পেশাল ক্যারেক্টার এনকোডিং (যেমন %20, স্পেস, হ্যাশ #, বা প্যারামিটারের ভ্যালুতে ? চিহ্ন) থাকলে ম্যানুয়াল স্প্লিট ভুল ডাটা দেয় অথবা ক্র্যাশ করে। এর জন্য স্ট্যান্ডার্ড হলো আধুনিক WHATWG URL API।

২. আধুনিক WHATWG `new URL()` ও `searchParams` API

Node.js-এ বিল্ট-ইন গ্লোবাল URL ক্লাস রয়েছে। যেহেতু req.url-এ ডোমেইন থাকে না, তাই সম্পূর্ণ ভ্যালিড URL অবজেক্ট তৈরি করতে দ্বিতীয় আর্গুমেন্ট হিসেবে হোস্ট (Base URL) পাস করা হয়: 

import http from 'node:http';

const server = http.createServer((req, res) => {
  // ডোমেইন বেইজ হিসেবে req.headers.host পাস করা হচ্ছে
  const fullUrl = new URL(req.url, `http://${req.headers.host}`);

  // ১. পাথনেম (Query ছাড়া শুধু রাউট পাথ)
  const pathname = fullUrl.pathname; // "/api/products"

  // ২. searchParams API ব্যবহার করে কুয়েরি রিড করা
  const category = fullUrl.searchParams.get('category'); // "electronics"
  const limit = fullUrl.searchParams.get('limit') || '10'; // "10"
  const hasSort = fullUrl.searchParams.has('sort'); // true অথবা false

  console.log(`[REQUEST] Path: ${pathname} | Category: ${category} | Limit: ${limit}`);
});

URLSearchParams এর প্রয়োজনীয় মেথডসমূহ:

মেথড উদাহরণ কাজ
get(key) searchParams.get('q') নির্দিষ্ট কি-এর প্রথম মান ফেরত দেয় (না থাকলে null)।
has(key) searchParams.has('page') কুয়েরিতে নির্দিষ্ট কি উপস্থিত আছে কি না (boolean)।
getAll(key) searchParams.getAll('tag') একই কি যদি একাধিকবার পাঠানো হয় (যেমন: ?tag=js&tag=web), সবগুলোর অ্যারে দেয়।
entries() for (const [k, v] of searchParams) সবগুলো কুয়েরি কি-ভ্যালু পেয়ারের ওপর লুপ চালানোর সুবিধা।

৩. HTTP Request Headers (`req.headers`) এর আদ্যোপান্ত

HTTP রিকোয়েস্টের সাথে ক্লায়েন্ট অতিরিক্ত মেটাডাটা পাঠায়, যাকে Request Headers বলা হয়। Node.js এই হেডারগুলোকে req.headers অবজেক্ট হিসেবে প্রোভাইড করে।

💡 হেডার কি-গুলো সবসময় Lowercase হয় কেন?
ক্লায়েন্ট হয়তো Authorization বা Content-Type লিখে বড় হাতের অক্ষরে পাঠিয়েছে। কিন্তু Node.js পার্স করার সময় সব হেডার কি-কে স্বয়ংক্রিয়ভাবে ছোট হাতের অক্ষরে (lowercase) কনভার্ট করে দেয় (যেমন req.headers['authorization'])। এটি RFC স্ট্যান্ডার্ড অনুযায়ী করা হয় যাতে ডেভেলপারদের কেস-সেনসিটিভ জটিলতায় পড়তে না হয়।

সবচেয়ে গুরুত্বপূর্ণ Request Headers:

হেডার নাম প্রবেশের উপায় ব্যবহারের উদ্দেশ্য
Host req.headers.host সার্ভারের ডোমেইন এবং পোর্ট (যেমন localhost:3000)।
Authorization req.headers['authorization'] ইউজারের JWT টোকেন বা API Key যাচাই করার জন্য (যেমন Bearer eyJhbG...)।
Content-Type req.headers['content-type'] ক্লায়েন্ট বডিতে কী ধরনের ডাটা পাঠাচ্ছে (যেমন application/json)।
User-Agent req.headers['user-agent'] ক্লায়েন্টের ব্রাউজার, ওএস বা ডিভাইস সম্পর্কে তথ্য।
Accept req.headers['accept'] ক্লায়েন্ট সার্ভারের কাছ থেকে কী ফরম্যাটে ডাটা আশা করছে।
