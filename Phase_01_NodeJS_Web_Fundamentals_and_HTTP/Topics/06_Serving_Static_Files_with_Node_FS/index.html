Serving Static Files (HTML, CSS, Images) with node:fs

MIME টাইপ ডিকশনারি, পাথ ট্রাভার্সাল সিকিউরিটি গার্ড এবং fs.createReadStream().pipe(res) দিয়ে হাই-পারফরম্যান্স ফাইল সার্ভিং।

১. স্ট্যাটিক ফাইল কী এবং ওয়েব অ্যাপে এর ভূমিকা?

একটি আধুনিক ওয়েব অ্যাপ্লিকেশনে ডাটাবেজ বা এপিআই রেসপন্সের বাইরে কিছু স্থায়ী ফাইল থাকে যা ব্রাউজারকে ডিসপ্লে বা ডিজাইনের জন্য দেখাতে হয়—এদেরকে বলা হয় স্ট্যাটিক ফাইলস (Static Files / Assets)। যেমন:

  • HTML ফাইলস: ওয়েবসাইটের পেজ স্ট্রাকচার (যেমন index.html, about.html)
  • CSS ফাইলস: ডিজাইন ও লেআউট (যেমন style.css)
  • JavaScript ফাইলস: ক্লায়েন্ট-সাইড ইন্টারঅ্যাক্টিভিটি (যেমন app.js)
  • মিডিয়া ও ফন্টস: ইমেজ (.png, .jpg, .svg), আইকন (favicon.ico) ইত্যাদি

২. MIME Type কেন এত বেশি গুরুত্বপূর্ণ?

আপনি যদি হার্ডডিস্ক থেকে একটি style.css ফাইল পড়ে ক্লায়েন্টকে পাঠান, কিন্তু হেডারে না বলেন যে এটি কী ফাইল, তবে আধুনিক ব্রাউজার (Chrome, Edge, Safari) সিকিউরিটি পলিসির কারণে স্টাইলশিট রেন্ডার করতে অস্বীকার করবে!

⚠️ সাধারণ ব্রাউজার এরর:
Refused to apply style from 'http://localhost:3000/style.css' because its MIME type ('text/plain') is not a supported stylesheet MIME type.

তাই আমাদের এক্সটেনশন অনুযায়ী সঠিক Content-Type হেডার পাঠাতে একটি MIME Types Map ব্যবহার করতে হয়:

ফাইল এক্সটেনশন MIME Type (Content-Type Header)
.html text/html; charset=utf-8
.css text/css; charset=utf-8
.js text/javascript; charset=utf-8
.json application/json; charset=utf-8
.png image/png
.svg image/svg+xml

৩. মারাত্মক সিকিউরিটি থ্রেট: Directory Traversal অ্যাটাক

যদি একজন ডেভেলপার সহজভাবে লেখেন: const filePath = path.join(publicFolder, req.url);

তাহলে একজন হ্যাকার অনায়াসে ব্রাউজারে বা curl দিয়ে রিকোয়েস্ট পাঠাতে পারে: GET /../../../../etc/passwd অথবা GET /../../package.json বা .env ফাইল! এতে সার্ভারের পাবলিক ফোল্ডারের বাইরে গিয়ে আপনার ডাটাবেজ পাসওয়ার্ড বা পুরো সার্ভারের সিস্টেম ফাইল হ্যাকারের কাছে চলে যাবে!

🛡️ ডিরেক্টরি ট্রাভার্সাল প্রতিরোধের নিয়ম:
ফাইল সার্ভ করার আগে সবসময় নিশ্চিত হতে হবে যে রিকোয়েস্ট করা ফাইলের আসল অ্যাবসোলিউট পাথ PUBLIC_DIR এর ভেতরেই অবস্থান করছে কি না: 
const safePath = path.join(PUBLIC_DIR, path.normalize(req.url));

// যদি ফাইল পাবলিক ডিরেক্টরির বাইরে যেতে চায়, সাথে সাথে ৪০৩ Forbidden!
if (!safePath.startsWith(PUBLIC_DIR)) {
  res.statusCode = 403;
  return res.end('Access Denied');
}

৪. `fs.readFile()` বনাম `fs.createReadStream().pipe(res)`

ফাইল পাঠাতে fs.readFile() ব্যবহার করলে পুরো ফাইলের সাইজ প্রথমে সার্ভারের র‍্যামে (RAM) লোড হয়। একটি ১০ মেগাবাইটের ইমেজ ১০০ জন একই সাথে চাইলে ১ গিগাবাইট র‍্যাম খরচ হয়ে সার্ভার স্লো হয়ে পড়বে।

আধুনিক স্ট্যান্ডার্ড: fs.createReadStream(filePath).pipe(res) ব্যবহার করা। এতে ফাইল ডিস্ক থেকে পড়ার সাথে সাথে নেটওয়ার্ক সকেটে পাইপ দিয়ে পাঠিয়ে দেওয়া হয়—মেমোরি খরচ শূন্যের কোটায় নেমে আসে!
