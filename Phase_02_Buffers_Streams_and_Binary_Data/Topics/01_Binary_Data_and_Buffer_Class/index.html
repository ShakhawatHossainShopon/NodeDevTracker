Phase 02: Buffers, Streams & Binary Data Topic 01 পাঠের সময়: ১৫ মিনিট

ওয়েব ব্যাকএন্ডে বাইনারি ডাটা ও Node.js Buffer ক্লাস

সার্ভার আর্কিটেকচারে র মেমোরি, বাইট সিকোয়েন্স, এনকোডিং ও পারফরম্যান্স-ক্রিটিক্যাল বাইনারি ডাটা ম্যানেজমেন্টের সম্পূর্ণ গাইড।

১. ওয়েব ব্যাকএন্ডে বাইনারি ডাটার প্রয়োজনীয়তা

ওয়েব ডেভেলপমেন্টের প্রাথমিক ধাপে আমরা প্রায়শই স্ট্রিং ও JSON অবজেক্ট নিয়ে কাজ করি। কিন্তু বাস্তবসম্মত প্রোডাকশন ওয়েব সার্ভারে বিপুল পরিমাণ ডাটা টেক্সট নয়, বরং বাইনারি ডাটা (Raw Octets / Bytes) হিসেবে আদান-প্রদান হয়।

ওয়েব ব্যাকএন্ডে বাইনারি ডাটা কোথায় ব্যবহৃত হয়?

  • মাল্টিমিডিয়া ফাইল ট্র্যাফিক: ইউজার যখন ইমেজ (PNG, JPG, WebP), PDF চালান বা ভিডিও আপলোড/ডাউনলোড করে।
  • নেটওয়ার্ক প্রোটোকল প্যাকেট: TCP সকেট ও TLS/SSL এনক্রিপশন লেয়ারের প্রতিটি প্যাকেট খাঁটি বাইনারি বাইট হিসেবে পরিবাহিত হয়।
  • HTTP হেডার ডিকোডিং: HTTP Basic Authentication হেডার (Authorization: Basic dXNlcjpwYXNz) Base64 এনকোডেড বাইনারি বাইটের সমন্বয়ে গঠিত।
  • ক্রিপ্টোগ্রাফি ও হ্যাশিং: পাসওয়ার্ড হ্যাশিং (bcrypt, Argon2), HMAC স্বাক্ষর এবং JWT টোকেনের গোপনীয় অংশ বাইনারি মেমোরিতে প্রসেস হয়।
💡 জেনে রাখা ভালো: আদি জাভাস্ক্রিপ্ট ব্রাউজারে স্ট্রিং ও DOM হ্যান্ডলিংয়ের জন্য ডিজাইন করা হয়েছিল, যেখানে র বাইনারি মেমোরি অ্যাক্সেসের সুযোগ ছিল না। Node.js সার্ভার-সাইড ব্যাকএন্ড হিসেবে প্রথম থেকেই উচ্চক্ষমতাসম্পন্ন Buffer ক্লাস প্রবর্তন করে।

২. Node.js `Buffer` ক্লাস কী এবং কীভাবে কাজ করে?

Node.js-এ Buffer হলো একটি গ্লোবাল ক্লাস যা অপরিবর্তনীয় নির্দিষ্ট আকারের (fixed-size) র মেমোরি চাঙ্ক নির্দেশ করে। প্রতিটি বাফারের উপাদান হলো একটি ৮-বিট আনসাইন্ড ইন্টিজার (Unsigned 8-bit Integer), যার মান 0 থেকে 255 (হেক্সাডেসিমেলে 0x00 থেকে 0xFF)।

V8 JavaScript Heap মেমোরি

সাধারণ জাভাস্ক্রিপ্ট অবজেক্ট, স্ট্রিং ও ভ্যারিয়েবল এখানে থাকে। V8 Garbage Collector নিয়মিত মেমোরি ক্লিন ও মুভ করে। বড় ডাটার ক্ষেত্রে মেমোরি ওভারহেড তৈরি হয়।

Node.js Buffer মেমোরি (C++ Layer)

বাফারের মেমোরি বরাদ্দ হয় V8 Heap এর সম্পূর্ণ বাইরে, র C++ কার্নেল মেমোরিতে (Raw Heap-less Memory)। এটি শূন্য মেমোরি কপি এবং উচ্চগতির নেটওয়ার্ক I/O নিশ্চিত করে।

Buffer ক্লাসের মূল বৈশিষ্ট্যসমূহ:

  1. ফিক্সড সাইজ (Fixed Length): বাফার তৈরি করার পর তার সাইজ সাধারণ অ্যারের মতো বাড়ানো বা কমানো যায় না।
  2. অকট্রেট অ্যারে (Uint8Array): বাফার আসলে জাভাস্ক্রিপ্ট Uint8Array কে ইনহেরিট করে, যার ফলে এতে অ্যারের মতো ইনডেক্সিং (buf[0]) করা যায়।
  3. গ্লোবাল মডিউল: কোনো ইমপোর্ট ছাড়াই গ্লোবালি অ্যাক্সেসযোগ্য, তবে আধুনিক ESM কোডে import { Buffer } from 'node:buffer'; ব্যবহার সর্বোত্তম চর্চা।

৩. বাফার তৈরি ও অ্যালটেশনের নিরাপদ পদ্ধতি

Node.js অতীতে new Buffer() কনস্ট্রাক্টর সমর্থন করত, যা অনিরাপদ হওয়ার কারণে বর্তমানে সম্পূর্ণ Deprecated। আধুনিক Node.js-এ বাফার তৈরির তিনটি প্রধান স্ট্যাটিক মেথড রয়েছে:

মেথড উদ্দেশ্য নিরাপত্তা স্তর
Buffer.alloc(size) নির্দিষ্ট সাইজের বাফার তৈরি করে এবং মেমোরির প্রতিটি বাইটে শূন্য (0) দিয়ে পূর্ণ করে। ১০০% নিরাপদ (Safe)
Buffer.allocUnsafe(size) নির্দিষ্ট সাইজের বাফার দ্রুত বরাদ্দ করে, কিন্তু মেমোরি শূন্য করে না (পুরোনো ডেটা থেকে যায়)। ঝুঁকিপূর্ণ (Potential Security Leak)
Buffer.from(data, encoding) বিদ্যমান স্ট্রিং, অ্যারে বা অন্য বাফার থেকে নতুন বাফার মেমোরি তৈরি করে। নিরাপদ ও বহুল ব্যবহৃত

কোড উদাহরণ: মেথডসমূহের ব্যবহার

import { Buffer } from 'node:buffer';

// ১. নিরাপদ এলোকেশন (১০ বাইট শূন্য দিয়ে পূরণ করা হবে)
const safeBuf = Buffer.alloc(10);
console.log(safeBuf); // <Buffer 00 00 00 00 00 00 00 00 00 00>

// ২. স্ট্রিং থেকে বাফার তৈরি
const strBuf = Buffer.from('Hello Web', 'utf-8');
console.log(strBuf); // <Buffer 48 65 6c 6c 6f 20 57 65 62>

// ৩. অ্যারে অফ বাইটস থেকে বাফার
const numBuf = Buffer.from([65, 66, 67]); // ASCII A, B, C
console.log(numBuf.toString()); // "ABC"
⚠️ সতর্কতা: কেন `Buffer.allocUnsafe()` ব্যবহারে সাবধান হবেন? allocUnsafe() সি-লেভেলে মেমোরি ক্লিন না করে বরাদ্দ দেয়। এতে আপনার অপারেটিং সিস্টেমের অন্যান্য প্রসেসের সংবেদনশীল ডেটা (যেমন পাসওয়ার্ড, ডাটাবেস কি, প্রাইভেট টোকেন) মেমোরি ফ্র্যাগমেন্ট হিসেবে থাকতে পারে। যদি আপনি এই বাফার পূরণ না করেই কোনো ক্লায়েন্টের কাছে রেসপন্স হিসেবে পাঠিয়ে দেন, তাহলে চরম সিকিউরিটি ডাটা লিক (Data Leak) ঘটতে পারে!

৪. Character Length বনাম Byte Length: ওয়েব ব্যাকএন্ডের চরম বাগ!

ওয়েব ব্যাকএন্ড ডেভেলপমেন্টে সবচেয়ে প্রচলিত কিন্তু মারাত্মক একটি বাগ হলো HTTP রেসপন্সে Content-Length নির্ধারণে স্ট্রিংয়ের .length প্রোপার্টি ব্যবহার করা।

জাভাস্ক্রিপ্ট স্ট্রিং বনাম UTF-8 মেমোরি

জাভাস্ক্রিপ্ট স্ট্রিং UTF-16 কোড ইউনিট গণনা করে। ইংরেজি অক্ষরের (ASCII) ক্ষেত্রে ১ ক্যারেক্টার = ১ বাইট। কিন্তু বাংলা, আরবি, চাইনিজ বা ইমোজির ক্ষেত্রে ১টি ক্যারেক্টার এনকোড হতে ২ থেকে ৪ বাইট পর্যন্ত জায়গা নেয়!

const english = "Hello";
console.log(english.length);                     // 5
console.log(Buffer.byteLength(english, 'utf-8')); // 5 (সমান)

const bangla = "বাংলা";
console.log(bangla.length);                      // 5
console.log(Buffer.byteLength(bangla, 'utf-8'));  // 15! (প্রতিটি বাংলা বর্ণ ৩ বাইট)

const emoji = "🚀";
console.log(emoji.length);                       // 2 (UTF-16 surrogate pair)
console.log(Buffer.byteLength(emoji, 'utf-8'));   // 4 বাইট!
🚨 HTTP তে কী সমস্যা হয়? যদি আপনি res.setHeader('Content-Length', bangla.length) দেন, তাহলে আপনি ক্লায়েন্টকে বলছেন ডাটার সাইজ ৫ বাইট। ক্লায়েন্ট (ব্রাউজার বা মোবাইল অ্যাপ) প্রথম ৫ বাইট গ্রহণ করেই কানেকশন ক্লোজ করে দেবে, যার ফলে বাংলা টেক্সট বা ইমোজি কেটে যাবে এবং ডেটা করাপ্ট হবে! সবসময় Buffer.byteLength() অথবা buffer.length ব্যবহার করতে হবে।

৫. বাফার এনকোডিং ও রিয়েল-ওয়ার্ল্ড ওয়েব কেস

বাফার থেকে ডেটা বিভিন্ন টেক্সট ফরম্যাটে রূপান্তর এবং উল্টো রূপান্তর করার জন্য Node.js বেশ কয়েকটি এনকোডিং সমর্থন করে:

  • 'utf-8': ওয়েবের ডিফল্ট টেক্সট এনকোডিং।
  • 'base64': ৮-বিট বাইনারি ডেটাকে ৬৪টি নিরাপদ ASCII ক্যারেক্টারে রূপান্তর করে।
  • 'hex': প্রতিটি বাইটকে দুটি হেক্সাডেসিমেল ক্যারেক্টারে (0-9, a-f) রিপ্রেজেন্ট করে।

রিয়েল-ওয়ার্ল্ড কেস: HTTP Basic Authentication ডিকোডিং

ব্রাউজার যখন Authorization: Basic YWRtaW46c2VjcmV0MTIz হেডার পাঠায়, সার্ভারে বাফার দিয়ে এটি সহজেই ডিকোড করা যায়:

// ইনকামিং হেডার: "Basic YWRtaW46c2VjcmV0MTIz"
const base64Str = "YWRtaW46c2VjcmV0MTIz";

// Base64 বাফার তৈরি করে UTF-8 এ রূপান্তর
const credentials = Buffer.from(base64Str, 'base64').toString('utf-8');
console.log(credentials); // "admin:secret123"

const [username, password] = credentials.split(':');
console.log(`User: ${username}, Pass: ${password}`);

৬. সরাসরি HTTP দিয়ে বাইনারি ফাইল বা ইমেজ সার্ভ করা

Node.js নেটিভ সার্ভারে res.end() শুধুমাত্র স্ট্রিং নয়, সরাসরি একটি Buffer গ্রহণ করতে পারে। এটি উচ্চগতির ফাইল সার্ভিং ও ইন-মেমোরি ইমেজ প্রসেসিংয়ের ভিত্তি।

import http from 'node:http';
import { Buffer } from 'node:buffer';

// ১x১ ট্রান্সপারেন্ট PNG এর Base64 বাইনারি ডেটা
const pixelBase64 = 'iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAQAAAC1HAwCAAAAC0lEQVR42mNkYAAAAAYAAjCB0C8AAAAASUVORK5CYII=';
const pixelBuffer = Buffer.from(pixelBase64, 'base64');

const server = http.createServer((req, res) => {
  if (req.url === '/pixel.png') {
    res.writeHead(200, {
      'Content-Type': 'image/png',
      'Content-Length': pixelBuffer.length // খাঁটি বাইট সাইজ (৬৮ বাইট)
    });
    return res.end(pixelBuffer); // সরাসরি বাইনারি বাফার পাঠানো
  }
});

server.listen(3000);

৭. গুরুত্বপূর্ণ টেকওয়ে ও বেস্ট প্র্যাকটিস

নিয়ম কেন গুরুত্বপূর্ণ?
কখনই new Buffer() ব্যবহার করবেন না এটি সিকিউরিটি ভলনারেবিলিটির কারণে ডিপ্রিকেটেড; সর্বদা Buffer.from() বা Buffer.alloc() ব্যবহার করুন।
HTTP Content-Length এ বাইট সাইজ দিন স্ট্রিংয়ের .length ক্যারেক্টার গোনে, বাইট নয়। মাল্টিবাইট ক্যারেক্টারের ক্ষেত্রে ডেটা ট্রাঙ্কেট হওয়া প্রতিরোধ করতে Buffer.byteLength() ব্যবহার করুন।
প্রয়োজনে Buffer.concat() দিয়ে একাধিক চাঙ্ক একত্র করুন ইনকামিং নেটওয়ার্ক স্ট্রিমের বাফার চাঙ্কগুলো একটিমাত্র বাফারে পরিণত করতে Buffer.concat([chunk1, chunk2]) ব্যবহার করা স্ট্যান্ডার্ড।
